# Noodl V5 — Smart Sweep, Exam Point Map and Coverage Ledger

**Status:** implemented in repository `main`, PRs [#25](https://github.com/SeraKah-1/noodl-gpt/pull/25), [#26](https://github.com/SeraKah-1/noodl-gpt/pull/26), [#27](https://github.com/SeraKah-1/noodl-gpt/pull/27). **Not yet independently verified on the production Sites host.**

## The user problem

Learners abandon long quizzes when most questions feel familiar. Raising the difficulty can omit facts and exceptions that may appear on the real examination. The solution reduces repetitive *actions*, not the question bank, and separates what the learner says they know from what they have demonstrated in scored practice.

## Product behavior now implemented

1. **Every bank question remains available.** Without an authored map, each question is treated as its own exam point. `exam_map` artifacts may group multiple question IDs **only** when the grouping is `author_reviewed` and includes an explicit equivalence reason and source references. Draft groups are split back into singleton points. New or unmapped questions also remain singleton points.
2. **Rapid Scan** shows five questions at a time, including choices but never marking or highlighting the answer key. The learner can select `Sudah tahu` or `Ragu` via buttons or keyboard (1/2). A separate explicit action marks all visible questions as learner claims with one click. No score, review event or spaced repetition credit is generated by these labels.
3. **Evidence calculations** use saved attempt snapshots and SRS due dates. Shown, self-claimed, answered correctly, answered incorrectly, stable across days, and untested variants are distinct. One correct variant is not counted as multiple individually tested questions.
4. **Audit Batch** includes unsure points first, mandatory repair for recorded wrong answers and a deterministic sample of known claims. A missed grouped point chooses a genuinely unshown sibling first where available. An audit creates an actual persisted Batch attempt using the original questions and scoring engine. If more marked points exist than the 20-question cap, the omitted count is displayed.
5. **Coverage Ledger** displays mapped bank questions, individually tested questions, source anchors mentioned by authors and each point's untested variants. These are different measures. Source anchors do **not** establish completeness of the original document or represent a prediction about the real examination.
6. **Full Exam** opens an unfiltered saved Standard attempt containing all original questions in that bank. Existing Standard, Batch, Survival, Time Rush, Quick 1/3, Flashcards and SRS mechanics are unchanged.

## Authored exam map schema

ChatGPT can build the map using source files in the conversation and save it through the existing MCP artifact write flow. Noodl does **not** add an uploader, OCR pipeline, LLM provider or independent verification backend.

```json
{
  "version": 1,
  "title": "Gastric acid secretion",
  "points": [
    {
      "id": "h2-receptor",
      "label": "Histamine acts at H2 receptors on parietal cells",
      "kind": "fact",
      "questionIds": ["question-123", "question-456"],
      "status": "author_reviewed",
      "equivalenceReason": "Both questions test the same receptor claim; exceptions remain separate.",
      "sourceRefs": [
        {"title": "Author's lecture PPT", "anchor": "Slide 12", "status": "provided"}
      ]
    }
  ]
}
```

This is illustrative only: never copy fabricated question IDs or slide references into a live bank. A legitimate map must use IDs that already exist in the bank, reference real source locations when available, and be saved with the correct bank revision. A `draft` group does not suppress any original question.

The saved map is itself an `Artifact` with `kind: "exam_map"`. The validator limits it to one active map per bank, up to 1,000 points and bank-valid question references. Existing question IDs and answer keys are not changed.

## Decision storage and sync

`SweepDecision` includes version, UUID, account owner, bank ID, bank revision, point ID, question ID, choice and timestamp. The local IndexedDB store partitions by owner and bank. Server-backed accounts sync decisions through authenticated `/api/coverage/decision` and `/api/coverage/decisions`; embedded ChatGPT uses `app_save_sweep` and `app_list_sweep`. Server writes reject ownership mismatches, invalid point/question membership, modified duplicate IDs and stale revisions.

- Local Guest saves decisions across refresh but must not claim cloud persistence.
- An offline decision stays pending until server acknowledgment. A stale bank revision becomes a visible conflict, not a silently rewritten decision.
- Decisions are **never stored in** the graded attempt answers or `ReviewEvent` tables. No inferred mastery score is awarded.
- The app routes questions into the existing persisted quiz engine rather than making a new fake question renderer.

## What the coverage statuses mean

| Status | Meaning |
| --- | --- |
| `unseen` | No saved presentation or verified answer for this point |
| `seen` | Presented, not demonstrated correct |
| `self_claimed` | Learner says they know it; no correctly scored answer yet |
| `tested` | At least one genuinely graded correct answer, not necessarily all grouped variants |
| `stable` | Correct on different sessions separated by at least 24 hours, with no newer observed miss or due SRS review |
| `needs_repair` | Latest recorded answer on a question in that point was incorrect |

These are limited summaries of **observations**, not validated medical knowledge, proficiency or examination readiness. A wrong or prompted Brain Dump answer remains different from a correct unassisted question attempt.

## Tests and acceptance gates

- `tests/exam-coverage.test.ts`: reviewed vs draft grouping, orphan references, no transfer of correctness to sibling variants, accurate counters, audit reproducibility, mandatory missed repair and unseen alternatives.
- `tests/offline.test.ts`: IndexedDB persistence, local Guest, account isolation, pending server writes, offline and conflict retention.
- `tests/server.test.ts`: authenticated private claim APIs, idempotence, foreign owner rejection, stale revision and no grade/SRS pollution.
- `scripts/smoke-sweep.mjs`: Chrome imports actual bank JSON, uses keyboard and bulk self-claims, confirms no score, completes a real Batch audit, reloads persisted evidence, and checks unfiltered Standard Full Exam.
- Existing Chrome UI, Debugger, and production build checks continue to run.

Source-level tests do not establish usability, retention benefits or absence of exam omissions for real users. Measure user time to completion, abandoned sessions, later test performance and missing source topics in a controlled study comparing **equal source content**.
